# Tinfoil Workbench 0.11 — validation record

Recorded 28 September 2026 for the 0.11.0 release. It lists what ran, what failed on the way, and what did not run. **The custom system prompt is optional and not required**; blank instructions remain covered by tests. The previous record is in [history/v0.10](history/v0.10/VALIDATION.md).

## Environment

- **Windows build machine:** Windows 11 Pro 10.0.26200 (x64).
- **Toolchain:** Node.js 24.21.0 LTS with npm 11.19.0; Electron 44.4.3, electron-builder 26.17.0, TypeScript 5.8.3, tinfoil 1.2.1, pdfjs-dist 5.4.149; Python 3.10 for the Python-runner tests; Playwright 1.63.0 with its bundled Chromium (build 1243) for the browser suites.
- **Android toolchain:** Temurin JDK 21.0.12.1, Android SDK platform 36 and build-tools 36.0.0, Capacitor 8.5.2, Android Gradle Plugin 8.13.0, Gradle 8.14.3.
- **Emulators:** Google APIs x86_64 system images, WHPX acceleration, headless with SwiftShader.

## Dependencies

- **Lockfile:** generated by `npm run bootstrap` from the exact direct pins. All locked packages resolve from registry.npmjs.org with integrity hashes. A clean reinstall (`npm ci` via bootstrap) followed by `npm run doctor` passed every entry.
- **Audit:** `npm audit --omit=dev` reports no known vulnerabilities. The full audit reports three moderate advisories in the dev-only chain `@capacitor/cli` → `xcode` → `uuid` (GHSA-w5hq-g745-h8pq). That chain edits iOS projects; it is not shipped and not used for Android. npm's only offered fix is downgrading the Capacitor CLI.
- **Install scripts:** npm 11.19 skips dependency install scripts unless approved. `electron-winstaller` (Squirrel.Windows only) and `esbuild` (its binary comes from the platform optional dependency) are recorded as denied. No other package declares one.
- **Electron binary:** Electron 44 has no install hook, which broke the 0.10 bootstrap/doctor/CI sequence on a fresh checkout. Bootstrap now runs the package's own installer, which verifies the binary against the pinned package's `checksums.json`.

Before these passes, the suites could not run on stock Windows. Nine hard-coded `/usr/bin/chromium`, and all failed with `UnicodeDecodeError` under a non-UTF-8 code page. `ui-activity.py` also failed **2 of 6** runs at one check that counted `.delegate-thinking` elements before the next animation frame rendered. After switching that check to Playwright's auto-waiting assertion it passed 10 of 10 runs. These were harness defects; no product code changed.

The first GitHub Actions Windows run failed one test, `python-runner.test.mjs` "generated supported files are collected…", which found 0 files instead of 1. The runner's TEMP is an 8.3 short path (`C:\Users\RUNNER~1\…`). `desktop/python-runner.mjs` compared each file's long `realpath()` with the short output directory, so its containment check silently dropped every Python output file for any user whose TEMP uses a short name. Pointing TEMP at a short alias reproduced this locally: the test failed with the old code and passed 9 of 9 with the fix, which compares resolved paths on both sides.

The desktop smoke test was also run from the VS Code integrated terminal. There it initially failed because the editor exports `ELECTRON_RUN_AS_NODE=1`, which starts Electron as plain Node. It passed once the variable was cleared. This is an environment issue, now noted in the README.

## Android

### Unit tests

The Node tests above include 18 for the Android host:

- **Vault:** round-trip; the envelope decrypts with `node:crypto` exactly as `desktop/vault.mjs` would; tampered, unknown-format and unwrap-failure cases fail without writing; writes are ordered, snapshotted and recover after a failure.
- **Command parity with `desktop/main.mjs`:** native confirmations, link validation, attachment, preview and import limits, the export and import round trip, the HTML save warning, PDF handling, delegation recheck and explicit Android messages for unsupported features.
- **Native-operation allowlist:** the fixed list, argument reduction and bounds.

### Device checks

`tests/android-device.py` ran against the final APKs:

| Device image | Android System WebView | `--debug --live` | `--release` |
|---|---|---|---|
| Android 16 (API 36), Pixel 7 profile | 133.0.6943.137 | **23/23** | **10/10** |
| Android 14 (API 34), Pixel 6 profile | 113.0.5672.136 | **23/23** | **10/10** |
| Android 11 (API 30), Pixel 4 profile | 83.0.4103.106 (stock) | The app refused to load and showed *Update Android System WebView*, as designed | — |

What those checks established:

- **Live enclave verification from the Android worker.** All five steps succeeded: `fetchDigest`, `verifyCode`, `verifyEnclave`, `compareMeasurements`, `verifyCertificate`. The router release was `v0.0.155`, with 17 models listed. A chat request with a deliberately invalid key reached the attested endpoint over EHBP and was rejected with "API authentication was rejected", with no fallback. No real key or account was used.
- **Network boundaries.** The renderer page cannot fetch anything (CSP). The worker reaches `atc.tinfoil.sh` but not `example.com`, plain HTTP, a look-alike host or another localhost port.
- **Disabled plugins.** Capacitor's HTTP, cookie and server-path plugins reject every call.
- **Durability.** A draft typed just before backgrounding survives a force-stop in both builds. The release build was tested through the real on-screen keyboard. The workspace reopens through the Android Keystore.
- **Back and native dialogs.** Back closes a dialog, then the drawer, then backgrounds the app with the same process. The deletion dialog is native and cannot be answered by the page; Cancel keeps the thread and confirming deletes it.
- **Layout.** The composer stays above the on-screen keyboard.
- **Release package.** It is not debuggable, the account view explains the API-key-only mode, and export, attach and import round trips work through the system document picker.

The emulator images are `userdebug` builds, on which WebView exposes DevTools for every app. That the release APK is not debuggable was therefore checked through its package flags and `run-as`, not through the absence of a DevTools socket.

### Issues found and fixed during validation

- **Unanswered plugin calls.** Capacitor ignores calls to methods a plugin does not declare, so the first plugin stubs left such calls pending forever. The stubs now declare every method of the plugins they replace and reject explicitly.
- **Secrets in debug logs.** Capacitor debug builds logged plugin arguments and results to logcat. Within the first run this included a wrapped workspace key, and it would include the unwrapped key on unlock. Logging is now disabled in every build (`loggingBehavior: "none"`); afterwards, logcat contained zero plugin payload lines on both emulator images.
- **Corrupted SDK metadata (build environment, not the app).** Android command-line tools 23.0 wrote NUL-filled `package.xml` files, which broke Gradle's SDK parsing. Reinstalling the packages with the classic `sdkmanager` from command-line tools 20.0 fixed it.
- **Android wording.** Onboarding asked for "an account or API key" on Android; it now asks for an API key.

## Not executed

- **No real account or key:** chat with a real API key and model response; Tinfoil Chat website sign-in (Windows); hosted web search and delegation against a real entitlement.
- **Windows hardware and configuration:** a clean, standard-user Windows machine (install, run and uninstall ran on the build machine); display scaling, high contrast, IME and the other manual items in [HANDOFF.md](HANDOFF.md); ARM64 Windows; code signing (not configured).
- **Android hardware and configuration:** physical Android devices, ARM hardware, tablets and foldables, TalkBack, non-English system pickers, OEM WebViews; upgrade from an earlier Android build (0.11.0 is the first).
- **iOS** is not supported.
